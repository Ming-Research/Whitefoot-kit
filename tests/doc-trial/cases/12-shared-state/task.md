Write a single file `main.wf` with entry `main`.

Have sixteen concurrent activities each add one twenty thousand times to one shared unsigned 64-bit counter, initially zero. After all those activities finish, observe the final counter. Separately, have four concurrent producers each publish the unsigned integers zero through 4,999 in order through one queue that holds at most eight values. Four concurrent consumers each remove five thousand values from that queue and add them to one shared unsigned 64-bit total. Each published value must be removed exactly once. After every producer and consumer finishes, observe the total and remaining queue length. Shared updates must preserve all increments and queue transfers under concurrent execution.

The expected counter is 320,000, consumed total is 49,990,000, and remaining queue length is zero. Return status one if the counter differs, two if the total differs, or three if the queue is not empty, in that priority order; write no output on those failures.

On success, publish the actual counter, total, and remaining queue length, in that order, as exactly 24 standard-output bytes: each value is an unsigned 64-bit integer encoded as eight little-endian bytes. Finish partial output transfers until all bytes are published. Return zero on success, or four on output error. Output the observed values, rather than the expected constants. Write nothing else to standard output or standard error. Use the supplied process and IO interfaces for startup and output, and close the startup directory permissions. No arguments or input are required. The trial supplies runtime setting WF_DRIVERS=4 to both programs; the runtime may use fewer drivers when the host IO route requires it.
